## 5. 冻结数据角色前必须核实的事项（清单）

1. **实际目录与版本**：官方 release 的目录结构（图像目录名、标注文件名）与本仓库 config 期望的
   `data/hrsid/images/` + `data/hrsid/annotations/{train,test}2017.json` 是否一致；
   官方 train/test 的**实际图像数与实例数**（以 json 实测为准）。
2. **切片 → 来源全景图的对应关系是否可得**（**这是"按来源场景划分"的前置条件**）：
   - 若文件名或标注字段中含来源场景标识 → 可按场景分组；
   - 若无法从数据本身恢复该映射 → **无法保证同一大图的不同切片不跨集**，
     此时须另行解决（联系作者 / 查官方划分说明），**不得默认「随机划分即可」**。
   - 用户已明确要求：避免**同一大图的不同裁片跨集**。
3. **与现有 SSDD 的重叠**：预期为 0（传感器与来源场景不同），但**必须实测**（比对图像内容/文件名/场景来源），
   不得假定。核实前不得宣称"无重叠"。
4. **是否已被任何既有实验使用**：本机记录显示**没有**；训练机器上须复核（第 1 节的适用范围提示）。
5. **磁盘与算力**：5604 个 800×800 切片的存储需求（约几 GB 量级）与训练机器磁盘余量。

## 6. 现成工具不能产出所要求的划分（重要）

`tools/dataset/semi_hrsid.py` 是 SSDD 划分脚本的**逐字拷贝**：它

```python
labeled_ind = np.random.choice(range(len(image_list)), size=labeled_tot, replace=False)
```
在 `train2017.json` 的**图像列表上随机抽**，**完全不感知来源场景**。

因此该脚本（及其驱动 `semi_hrsid.sh`）产出的 `@N` / `@N-unlabeled` 划分
**不满足**「同一大图的不同裁片不跨集」的要求。

**结论**：若 HRSID 合格，须**另写按来源场景分组的划分脚本**（记住分组键的来源与生成命令），
**不得**把 `semi_hrsid.sh` 的输出直接当作 dev/final 划分。这是本阶段新增的一项实现工作，不在本轮执行。

## 7. 评价口径（不得混用）

- 用 HRSID 评价应称为**跨数据集泛化验证**；**不等于** SSDD 的**同分布性能**。
- 两个数据集的指标**不可直接相减**并当作"增益"：传感器、分辨率、切片尺度、场景复杂度、
  标注规范、类别定义均不同（SSDD 以近岸/港口场景为主，HRSID 为 800×800 全景切片、小目标比例更高）。
- 因此 HRSID 上的结果**不能替代** SSDD 上的主指标结论（见 [[feedback-main-metric-primary]]），
  只能作为**独立的域外参照**并列报告。
