## 0. 一句话

**只在 `sup2` 分支**的 ROI 分类损失上，对**被匹配器判为背景、且框面积极小**的那部分样本，把逐样本损失权重从 1.0 提到 `1+λ`（λ=1.0）。**不新增参数、不新增损失项、不改采样器、不改推理与后处理。**

## 1. 改哪里

### 1.1 精确位置

现配置（`ablation_configs/fold*/**/b0.py`）的 RCNN 是 `StandardRoIHead` + `Shared2FCBBoxHead`：

- 分配器：`MaxIoUAssigner(pos_iou_thr=0.5, neg_iou_thr=0.5, min_pos_iou=0.5, match_low_quality=False)`
  → 每个 ROI 只有三种结局：正（≥0.5）、背景（<0.5）、忽略。
- 采样器：`RandomSampler(num=512, pos_fraction=0.25, add_gt_as_proposals=True, neg_pos_ub=-1)` → 每图约 128 正 / 384 背景。
- 分类头：`Shared2FCBBoxHead(num_classes=1)`，`loss_cls=CrossEntropyLoss(use_sigmoid=False, loss_weight=1.0)` → 二路 softmax。

改动落在 mmdet 既有链路上（**不编辑 `thirdparty/mmdetection`**，在消融 checkout 下新建子类）：

```
BBoxHead._get_target_single(...)：
    labels = pos_bboxes.new_full((num_samples,), self.num_classes, ...)   # 背景
    label_weights[-num_neg:] = 1.0                                        # ← 唯一改动点
BBoxHead.loss(...)：
    avg_factor = max(torch.sum(label_weights > 0).float().item(), 1.)
    loss_cls_ = self.loss_cls(cls_score, labels, label_weights, avg_factor=avg_factor, ...)
mmdet cross_entropy(pred, label, weight=...)   # 文档字符串原文：Sample-wise loss weight
```

本机 mmdet 2.16 上**已实测确认**：

1. `label_weights` 作为 **per-sample** 权重进入 `CrossEntropyLoss`，在 `F.cross_entropy(..., reduction='none')` 之后按元素相乘 → 逐样本生效，不是逐类。
2. `avg_factor = sum(label_weights > 0)`：**分母只数"有效样本数"**（权重 > 0 的个数）。把它从 1.0 抬到 2.0 仍是 > 0，**分母不变**。
   **因此正确表述是**：加权后**这部分负样本的损失贡献确实增大**（分子变大），**分母（归一化基准）不变**；这**不等于**"损失整体尺度不变"——`loss_cls` 的数值是会变大的。第一版写成"不是整体放大损失"，措辞已更正。
3. `add_gt_as_proposals=True` 使**已加入候选的、已标注的 GT 框**以正样本身份进入（权重保持 1.0）。**它保护不到漏标船只，也保护不到"包含船只但与任何标注都不匹配"的 ROI**——这类 ROI 仍会被判为背景并吃到加权。此点直接决定 Stage 0 的结论权重（见 §4.4、§6）。

### 1.2 改动内容（唯一的一处）

覆盖 `get_targets`，对每张图、每个采样后的 ROI：

```python
w_i = 1 + LAMBDA * 1[label_i 是背景] * 1[area_i < 32**2]
```

- **公式中没有分数条件**，因此命名不用"高分"。
- `LAMBDA = 1.0`，**事先固定、不搜索**；背景小框权重上限 2.0。
- 忽略样本（权重 0）不变；正样本权重保持 1.0。
- `area_i = (x2-x1) * (y2-y1)`，ROI **还原到原图尺度**后计算。

#### 1.2.1 面积口径的两个偏差（必须如实报告）

- **训练侧用「采样 ROI 面积」＝ RPN 提案框，回归之前**；**诊断侧（报告 §5.6）用「最终回归框面积」**。提案框回归后会改变大小与位置，**二者不保证对应**：本方案实际加权的集合与诊断所描述的集合只是**近似同一批**，不是同一集合。
- **原图尺度换算必须按实际增强逐图核对**：`sup2` 的 pipeline 是
  `RandResize(img_scale=[(1333,400),(1333,1200)], multiscale_mode='range', keep_ratio=True)`
  → **每张图的缩放比不同**，不能用常量换算；必须逐图从 `img_metas[i]['scale_factor']` 读取（x/w 除以 `scale_factor[0]`、y/h 除以 `scale_factor[1]`）。
  （`sup1` 用固定 `Resize((1333,800))`；本版不改 `sup1`，此处仅说明两者差异。）
- 验收时须打印被加权 ROI 的面积分布（原图尺度），以便与诊断侧的最终框面积分布对照。

### 1.3 作用分支与边界（首版收窄）

| 项 | 取值 |
|---|---|
| 生效分支 | **只有 `sup2`**（由 pipeline `ExtraAttrs(tag='sup2')` 写入的 `img_metas[i]['tag']` 判定） |
| 不生效 | `sup1`（光学/另一路有标注流）、`unsup_student` / `unsup_teacher`、RPN、FPN、回归损失、采样器 |
| 推理路径 | **完全不变**（不新增分支、不改 score/NMS 阈值、不改 `inference_on='teacher2'`） |
| 后处理 | 与六组相同的冻结参数（rcnn score_thr 0.05 / nms 0.5 / max_per_img 100） |
| 可训练参数 | **新增 0 个**；`state_dict` 键与 B0 完全一致 |

首版不同时改 `sup1`、也不进入伪标签分支。伪标签分支不加，沿用仓库既有原则（`foreground_head.py` 首段原文）：缺失的伪框**不构成背景**。这不是新增假设，是沿用。

## 2. 为什么可能有效

### 2.1 支持证据（`results/run_001`，三折新 B0）

| 量 | fold6_b0 | fold7_b0 | fold8_b0 |
|---|---|---|---|
| 背景误检总数（legacy bkg） | 2401 | 2578 | 2569 |
| 其中小框（bbox < 32²）占比 | 0.848 | 0.845 | 0.809 |
| 分数 ≥0.7 ∧ bbox<32² 的框数 | 1008 | 1092 | 1073 |
| 其中判为背景 | 693（68.8%） | 774（70.9%） | 734（68.4%） |
| 该背景子集中对同图所有 GT 最大 IoU < 0.1 | 672（97.0%） | 760（98.2%） | 724（98.6%） |
| 同一子集中最大 GT IoU ∈ [0.1,0.5) | 21 | 14 | 10 |
| 逐图 bkg 计数折间 Pearson | 0.973 / 0.977 / 0.978 | | |
| 三折 top-quartile 硬图交集 | 50（随机期望 3.62） | | |

推理链：这些框**已经通过 RPN、并被分类头给了 ≥0.7 的分数**，所以干预点最直接的就是**分类头在背景样本上的损失**；而"小框 + 与任何 GT 重叠都极低"这一形态在三折都成立且逐图相关极高，说明是可复现的分布特征，不是单折噪声。

### 2.2 与"前景辅助头"（E2，mAP −0.029）的实质区别

| 维度 | FG 辅助头（E2，已做） | 本方案 |
|---|---|---|
| 结构 | **新增** FPN 上的密集卷积头（3×3 + 1×1）与一组**新参数** | **不新增任何参数、不新增模块** |
| 损失 | **新增**一项 Gaussian focal loss（α=2, β=4），逐像素 | **不新增损失项**；只改既有分类 CE 的逐样本权重 |
| 监督信号 | 框中心截断高斯**密度图**（软目标） | 既有 **0/1 分类标签本身**（硬标签） |
| 粒度 | 特征图逐像素 | ROI（框级），且只落在背景样本上 |
| 干预面积 | 共享 FPN 特征被新头拉扯 | 不改特征，只改一部分负样本的相对权重 |
| 推理 | 训练时辅助分支 | 与 B0 完全一致 |

E2 的 −0.029 **成因至今未确认**（`fg_replay_diagnostic_20260926.json` 只证明损失与梯度非零），既不能用来否定本方案，也不构成支持。

### 2.3 明确不作为证据的东西

**不**声称"背景误检数量减少会带来 mAP 上升"。§2.1 是错误分布描述，不是增益预测。

## 3. 如何避免误伤真实小目标

**机制上的保护**

1. 只作用于**判为背景的 ROI**；真实小 GT 产生的正 ROI 权重保持 1.0。
2. `add_gt_as_proposals=True` → **已标注且已加入候选的 GT 框**永远是正样本。
3. 不动采样器（`num=512 / pos_fraction=0.25`）→ 每批正样本数量不变。
4. `neg_pos_ub=-1`、`match_low_quality=False` 不变 → 无低质量匹配重贴标签、无额外筛负样本。
5. `avg_factor` 不变 → 归一化基准不变，不挤占正样本与回归项的梯度比例。
6. λ=1.0 单值、32² 单值，均不搜索。
7. 实现处加断言自检（见 §5.1）。

**保护不到的地方（如实声明，收窄第一版的说法）**

- `add_gt_as_proposals=True` 保护的是**已标注的 GT 框**；对**漏标船只**、以及**任何"含船但未与标注匹配"的 ROI**没有保护作用。这类 ROI 照样被判为背景并吃到加权。
- 因此在**漏标密集**的训练图上，本改动等于**主动学习"未标注的亮目标 = 背景"**。
- 这一风险不是理论上的：Stage 0 已在本轮 `sup2` 的三张训练图上观察到该形态（`stage0_record_20260929.md`，fold6/`000020.jpg` 为港口场景、单框只覆盖一条亮带、同图大量未标注亮目标）。该风险是否可接受，**由 Stage 0 的案例核查裁定**（§6）。
- 另一残余风险：抑制背景小框会通过共享 FC 权重影响小框正样本分数，可能压低真实小船召回。故 APs 与 mAP 并列判定（§5）。

## 4. 数据角色与预算（硬约束）

### 4.1 现有数据的事实（本轮实测）

| 文件 | 图像 | 标注 |
|---|---|---|
| `annotations/train.json` | 928 | 2041（**928 张全部有标注**） |
| `annotations/test.json` | 232 | 546（232 张全部有标注） |
| `semi_supervised/instances_train2017.{6,7,8}@3.json` | 各 3 | 3 / 4 / 5 |
| `semi_supervised/instances_train2017.{6,7,8}@3-unlabeled.json` | 各 925 | 0 |

- **`test.json` 与 `train.json`、与各折的 `@3` 及 `-unlabeled` 完全无重叠**（实测交集均为 0）。
- 三折的 3 张标注图，其框数与 `train.json` 中同图标注**完全一致、无遗漏**（逐图核对，见 Stage 0 记录）。

### 4.2 由此得出的结论

- **现有数据里切不出干净的独立开发集**：928 张训练图在 `train.json` 里都有标注，但除 3 张之外全部作为**未标注池**参与过训练；从池子里切出来的图都已被训练"看过"。
- 因此 `D_dev` / `D_final` **只能来自新的、此前未参与训练的 SAR 图像/场景**。这正是待确认项：数据名称、路径、与现有 SSDD 图像/场景的重叠情况。
- **在数据角色冻结之前，不做 Stage 0 的 60 案例抽查**（它需要一份 dev 上的预测，而这份预测只能来自冻结后的 dev 划分）。

### 4.3 三个角色的规则

| 角色 | 用途 | 触碰次数 |
|---|---|---|
| `D_train` | 只在并入训练时使用 | 训练内 |
| `D_dev` | 案例核查、诊断、训练侧验收 | 可反复，但不作最终结论 |
| `D_final` | 最终判定 | **只评一次** |

- 划分规则**事先固定**，按**场景/来源分组**切分，不按图像随机切，避免同场景跨划分泄漏；归属在开训前写死并记录哈希。
- **B0 与改动组预算必须相同**（同折标注、同未标注池、同迭代数、同 seed，唯一差别是 §1.2 那一处）。若把 `D_train` 并入训练，**B0 必须在同一扩充训练集上重训一次**，否则两组不可比。
- **不得把当前 232 图测试集的误检回灌训练**：不得把它的 FP 当负样本、不得用它的图像微调、不得据它调 λ 或后处理阈值。
- **换标注折（如 fold9/10）但仍只评这 232 图，不算新的独立测试集**，不能作为最终判定依据。
- **232 图的角色**：已被用于挑选方案（fold6 选 PG），**已不是留出集**；新方案里至多做现象描述/回归观察，不作 B0 vs 改动组的判定证据。
- **最终测试集不参与 Stage 0。**

## 5. 如何验证

### 5.1 训练侧验收（判"实现是否生效"——不看效果指标）

| # | 检查 | 通过标准 |
|---|---|---|
| A1 | 存在性 | 被加权 ROI 数 > 0；断言这些 ROI 的 `label` **全部是背景** |
| A2 | 公式 | 权重取值集合 ⊆ {1.0, 1+λ}；取 1+λ 的位置与「背景 ∧ 原图尺度面积 < 32²」**逐一对应** |
| A3 | 隔离 | 同一次前向的 loss 分解：除约定的分类损失外，其余各项与 λ=0 对照**逐位相同**（或 ≤ 数值噪声） |
| A4 | 分支隔离 | `sup1` / `unsup_*` 分支被加权 ROI 数 == 0 |
| A5 | λ=0 回归 | **λ=0 必须与 B0 数值等价**（同 batch、同权重下前向与 loss 逐位一致）——这一条不过，说明实现改动了别的东西 |
| A6 | 参数 | 新增可训练参数 == 0；`state_dict` 键与 B0 **完全一致**，可直接加载 B0 权重 |

A5 与 A6 是"只引入一个改动"的可执行判据。

### 5.2 效果指标（报告，但**不能**代替 §5.1 的验收）

- **主指标：COCO mAP**（`bbox_mAP`），只看它判定增益。
- **并列报出**：`APs`、`AP75`、`AR@100`。`APl` / `AR_l@1000` 不作结论（COCO 口径 large 仅 2 GT）。
- Δ 由**未舍入**值计算；多折按**逐折配对 Δ 再等权平均**。
- 误检数、高分小框背景计数可以**报告**（含在 dev 上做，以冻结口径 `high_score_small_bkg_iou_lt_0.1` 统计），但**不比照任何阈值当作"是否触达"的判据**——第一版"下降 ≥20% 即触达"的门槛已**撤销**：触达由 §5.1 证明，误检降幅属效果面。

### 5.3 失效模式（**不声称穷尽**；未被预见的失效同样作否定）

| 类 | 含义 | 处置 |
|---|---|---|
| F1 | **实现未生效**（A1–A6 任一不过） | 改实现，**不判方向** |
| F2 | **生效但无精度收益**（dev 与 D_final 上 ΔmAP ≤ 0；或逐折方向不一致、等权平均 ≈ 0） | 方向不成立 |
| F3 | **以真实小目标召回下降换取误检减少**（ΔAPs < 0 且量级 ≥ ΔmAP） | 方向不成立（代价大于收益） |
| F4 | 背景小框计数减少而 mAP 同降（与现有反证同型：fold7 −20/−0.0200、fold8 −62/+0.0215、fold6 +56/+0.0343） | 方向不成立 |
| F5 | Stage 0 案例核查判定该加权会把**真实（未标注）目标当背景** | **方案前提不成立**，在实现前即否定 |

F1 与 F2/F3 必须分开：F1 只是实现问题，不能记成"方向无效"。

### 5.4 执行顺序

1. **阶段一（数据确认）**：确认独立 SAR 数据的名称、路径、与现有 SSDD 的重叠；冻结 `D_train` / `D_dev` / `D_final`。
2. **阶段二（Stage 0）**：案例核查（§6）。**在它给出结论之前不写实现代码。**
3. **阶段三**：实现 + §5.1 验收（先在 λ=0 上跑通 A5/A6）。
4. **阶段四**：训练改动组与同预算 B0，在 `D_dev` 上评估。
5. **阶段五**：仅当未触发 F1–F3 时，在 `D_final` 上评一次。

## 6. Stage 0：代表案例核查（决定监督方式）

**IoU 极低 ≠ 空间上远离 GT**：很小的框整体落在某个大 GT 框内时 IoU 也会很低。所以 `[0,0.1)` 档**不能**一概当"纯背景"。要区分四类：

| 类 | 含义 | 对本方案的含义 |
|---|---|---|
| A 真实背景 | 水面杂波、岸线、码头结构、无船区域 | 加权**正确** |
| B 尺度／定位偏差 | 框落在某 GT 内但只覆盖局部，或远小于 GT | 问题在回归侧，加权可能误伤 |
| C **疑似漏标** | 框正好在真实船上但无标注 | **不得**当背景抑制；方案前提受损 |
| D 无法判断 | 证据不足 | 不计入 A/B/C，单独列出 |

**抽样规格（已定）**

- **固定随机种子**（写死在脚本里，随产物记录）。
- 按分数 `[0.7,0.9)` 与 `≥0.9` **各抽 30 个**，共 60 个。
- **尽量每图一个**（先按图去重，再按图轮转取样）；**不足时报告实际抽到的数量**，不凑数、不重复。
- 样本总体：dev 划分上"判为背景 ∧ 原图尺度框面积 < 32² ∧ 与同图所有 GT 最大 IoU < 0.1"的框（与报告 §5.6 同口径）。
- 抽样脚本：`sample_stage0_cases.py`（复用 `error_analysis.py` 的冻结原语 `iou / load_gt / load_predictions / legacy_match`，**不重写匹配逻辑**）；产出 CSV + 逐案例裁剪图（含 GT 叠加）供人工判读。

**不设任意占比自动判"通过"。** 疑似漏标（C）**逐个核查**，不等到"占主导"才处理；C 类一经确认，即按 F5 处理。

**训练图完整核查（成本低，已在本轮完成）**：三折各 3 张 `sup2` 标注图 + 其标注已全部核对，结果见 `stage0_record_20260929.md`。

## 7. 已知限制（如实列出）

1. **面积口径偏差**（§1.2.1）：加权对象是**回归前提案框**，证据对象是**最终回归框**，两者只是近似同一批。
2. **成因未归因**：这些框"通过了 RPN 并被分类头给了高分"是事实，但"为什么给高分"本轮未归因。本方案赌的是"提高背景样本的相对惩罚能压低这类分数"，这是**假设**，不是已证结论。
3. **单折不可外推**：第二轮已证（fold6 +0.034 vs 两折平均 +0.0005）。本方案同样需要多折逐折配对。
4. **λ=1.0 任选**，无先验依据；可能太小（无效）或太大（误伤）。
5. **232 图已污染**，不能再充当任何"独立"角色。
6. **首版仅 `sup2`**：若 `sup1`/伪标签分支是这类误检的主要来源，本版作用面不足。这属于"实现范围"而非"方向"问题。
